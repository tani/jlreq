# M5 数値検証: stretch/shrink priority・end_adjust 近似の実測

対象: `stretch_priority` / `shrink_priority` / `end_adjust` の近似が、実際の文章で
行分割にどう効くかを、uplatex 参照系（pTeX ネイティブ JFM）との比較で検証する。
（再現物: `poc/m5-corpus-body.tex`, 抽出比較 `poc/m5_lines.py`。）

## 方法

- コーパス: 実文 3 段落（P1 区切り約物多め / P2 引用多め / P3 括弧類多め）。
  各 120–160 字。`\hsize=200pt`（全角20字）・10pt・`zw=10pt` で統一。
- 両系統で同一ソースをコンパイル（uplatex+dvipdfmx・pdflatex=本バックエンド）、
  `pdftohtml -xml` で全グリフの (x,y) を抽出し、行ごとの先頭・末尾グリフから
  ブレークポイント列（ソース中の文字オフセット）を再構成。
- 追加実験: バックエンドの end_adjust 畳み込みを無効化した版
  （`\def\jlreqpdf@addendadj#1{}` で上書き）も同条件で組み、
  畳み込み自体の効果を分離した。

## ブレークポイント列（行末オフセット、図内は文字数）

| 段落 | upLaTeX (pTeX JFM) | pdfLaTeX バックエンド | endadj 無効化 |
|---|---|---|---|
| P1 | 20, 39, 58, 78, 98, 118, 130 | **20, 39, 60, 80, 99, 119, 130** | 20, 39, 58, 78, 97, 117, 130 |
| P2 | 20, 41, 62, 83, 104, 124 | **20, 41, 62, 83, 104, 124** | （同左） |
| P3 | 19, 40, 61, 81, 102, 122, 143, 153 | **19, 40, 61, 82, 103, 123, 145, 153** | 19, 40, 61, 82, 103, 123, 145, 153 |

行数は 3 段落とも全一致（7/6/8 行）。差分はブレークポイントの 1–2 字のズレのみ。

## 分岐点の解析

### P1（差 = L3–L7）: end_adjust 畳み込みの効果そのもの

- バックエンドは行末両端揃え時に、クラス 6/7（句読点）の次のグルーの shrink を
  end_adjust 分（+0.5zw）だけ強めるため、約物の直前・直後で「あと少し詰める」
  行が選ばれやすい → 各行に 1–2 字多く収まり、upLaTeX より遅い段で折れる。
- 畳み込み無効化版のブレークポイントは **upLaTeX とほぼ一致**（58,78,97,117 vs
  58,78,98,118：4 ポイント中 3 完全一致、残り 1 差 = メトリクス差）。
  ⇒ **P1 の発散の主要因は end_adjust 近似で、近似が意図通りに機能している**
  （ltj `priority=true` の行末詰めを shrink 畳み込みで再現した方向性と一致）。
- P1-L3 の関与ペア 。→咲（6→0）: jlreq ペア `{0.5, 0.25, 0.0, ratio=0, spri=-1, shpri=0}` +
  endadj@6 `{0, 0.5}` → 実効 shrink 0.5zw。pTeX ネイティブ JFM は end_adjust を
  持たずより早い点で折れる。

### P2（差なし）

- 全ブレークポイント完全一致。引用括弧（「」『』）周辺のグルー値が pTeX JFM と
  jlreq JFM で一致し、伸縮吸収できる弾力が十分あったため。

### P3（差 = L4–L8）: JFM 自体のメトリクス差（優先度・end_adjust の影なし）

- 差の出る 4 ポイントは常に 1–2 字遅く折れる（81→82, 102→103, 122→123, 143→145）。
  畳み込み無効版と同一のブレーク列 ⇒ end_adjust 非関与。
- 関与ペア: は→（（15→1, `{0.5, 0.25, 0.5, ratio=1, spri=-1, shpri=-2}`）、》→を
  （2→0, `{0.5, 0.25, 0.5, ratio=0, spri=-1, shpri=-2}` + endadj@2 `{0,0.5}`）。
  約物直前側の 0.5zw グルーを保持し続ける収まり方が pTeX ネイティブと
  微妙に異なることに由来（jlreq JFM と pTeX JFM のデータ差）。
- **stretch/shrink priority について**: 全 402 ペアの優先度フィールド分布は
  `(spri,shpri) = (0,0):217, (-1,0):81, (0,-1):33, (0,-2):15, (-1,-1):14, (-1,-2):42`。
  今回の分岐点に現れたペアの spri/shpri はすべて（-1, 0）または（-1, -2）、
  かつ参照系（pTeX）は優先度処理を**行わない一片組**なので、
  **優先順位近似が今回のブレーク選択を変えることはない**（差は全部データか
  end_adjust）。なお本バックエンドの一片組での「優先度落ち」はドキュメント済の
  近似であり、その直射では発散が観測されなかった。

## M5 内部の修正（数値裏付けつきのバグ修正）

`\jlreqpdf@addendadj` は実配置上、csname 直後の `\fi` を第 2 引数として食い、
end_adjust 詰め量が**データに関係なく常に 1zw = 10pt**になっていた（4 変種共通の
静かな誤差）。今回の比較実験で end_adjust 畳み込みの正当性を特定できたことに伴い、
ブレース群駆動の走査で直した:

| クラス | end_adjust データ（zw） | 修正後 shrink に加算される量 | 旧実装（バグ） |
|---|---|---|---|
| 2（閉じ括弧） | `{0}{0.5}` | **0.5zw** | 1zw（無条件） |
| 5（中点） | `{0}{0.25}` | **0.25zw** | 1zw |
| 6/7（句読点） | `{0}{0.5}` | **0.5zw** | 1zw |
| 6/7（-b 変種） | `{-0.5}{0}{0.5}` | **0.5zw**（負の値は H1 が担う） | 1zw |

修正後も全スイートは ALL PASS（`endadjust.log` に Overfull も出ない）。
ブレース群走査なのでフィールド数が増えても安全（-b の 3 フィールド形式可）。

## 結論（compat 行列の素材）

| 項目 | 状態 | 根拠 |
|---|---|---|
| end_adjust 近似（shrink 畳み込み） | **implemented（実測で機能確認）** | P1 で約物両側の折り位置を意図方向（行末で 0.5zw 詰め）に移動。畳み込み遮断で upLaTeX と一致 |
| stretch/shrink priority 近似落ち | **limitation agreed（近似落ち、実害なし）** | 全 9 分岐点で優先度非依存を実測。優先度データは保持（.def の 402 ペアに spri/shpri 全保持） |

`pdftohtml -xml` 抽出 → `poc/m5_lines.py` で同じ表が出る。
